# @hoardodile/plugin-manga

Manga reader content plugin: chapter directory, scroll and paged modes,
per-page comments and reading-position restore. Supports page-folder
resources (subdirectories become chapters) and single-file comic
archives — CBZ/zip, CBR/rar, CB7/7z, CBT/tar, EPUB — whose pages are
materialized on first preview via the host's `extractArchive`.

## Importing a chapter book

Two equivalent ways to get a multi-chapter book into hoardodile:

- **One archive**: upload a single CBZ/CBR/CB7/CBT (chapter
  subdirectories inside the archive become chapters), or an EPUB with
  image pages. Non-zip formats list/extract through the bundled 7-Zip
  binary, so uploads of rar/7z/tar need that optional package installed.
- **A whole book folder**: `importLocal` is non-recursive per *direct
  item*, but a directory item is packed recursively — put the whole
  book folder (with `第1话/`-style chapter subdirectories) into the
  import source, or browse to its parent in the folder importer and
  import it: it lands as ONE resource whose nested chapter paths the
  reader groups into chapters.

## Dev loop

This plugin is developed entirely through the plugin toolchain — no
hoardodile server, no web app:

```bash
pnpm build          # bundle manifest + client + server hooks into dist/
pnpm dev            # watch-build and serve the workbench (http://127.0.0.1:5199)
pnpm detect:smoke   # run detect against testdata/pages through the real sandbox
pnpm test           # vitest
```

`pnpm dev` captures the server-side hook results (`detect`, `sourceMeta`,
`searchMeta`, `listFiles`, `coverLocal`) from the real worker sandbox and
feeds them to the workbench, so the iframe receives the same context the
app would push. It serves the flat page volume (`testdata/pages` via
`--data`); point it at `testdata/cbz` or `testdata/book` to work on the
archive / folder paths. Individual hooks can also be run or benchmarked
directly:

```bash
pnpm exec hoardodile plugin run listFiles testdata/pages --plugin-dir dist
pnpm exec hoardodile plugin run listFiles testdata/cbz --plugin-dir dist
pnpm exec hoardodile plugin bench listFiles testdata/pages --plugin-dir dist
```

Archive hooks materialize into a scratch cache under the OS temp dir
during `plugin run`/`dev`, mirroring the server's `local/cache` layout.

## testdata/

Committed fixture volumes under a single `testdata/` root, regenerated by
`pnpm testdata`. Every volume is a flat directory — a resource holds
either a page folder or a single archive, never both:

- `testdata/pages/` — a synthetic volume of ten generated pages,
  `1.png` … `10.png`. The filenames are deliberately unpadded so
  lexicographic and natural ordering disagree — the reader must show
  them in page order. Each page carries one marker bar per page number,
  so the current page is readable at a glance.
- `testdata/cbz/` — a two-chapter DEFLATE CBZ (`第1话/` and `第2话/`,
  five pages each, page numbers restarting per chapter) carrying the
  side-car junk real CBZs ship with (`ComicInfo.xml`, `Thumbs.db`) —
  `listFiles` must skip those and keep only image pages.
- `testdata/cbz-stored/` — the same book re-packed with STORED entries,
  covering the uncompressed boundary of the container codec.
- `testdata/cbz-nasty/` — deep nesting, a ~90-char directory name and
  `#`/spaces/parens in page names.
- `testdata/book/` — the same book as a *folder* (chapter
  subdirectories), standing in for the folder-import path.

Real-world samples live in `testdata-real/` (git-ignored; not
committed): small public-domain comics and EPUBs downloaded from the
Internet Archive, exercised through the sandbox during development.

```bash
pnpm testdata:real   # fetch/verify samples, then run the hook suite
```

Known container limits: password-protected (encrypted) zip entries are
rejected with a clear error, and ZIP64 archives (>4 GiB / >65535
entries) fall back to the yauzl parser without a dedicated fixture.

The fixture volumes hold resource content and nothing else: `detect`
rejects a page folder that mixes in non-image files, so a stray README
there would make the plugin stop matching its own fixture.

## Architecture

- `src/core/` — framework-agnostic domain logic, fully unit-tested:
  source-shape classification (`format.ts`), chapter grouping and order
  (`chapters.ts`), the linear book model and navigation (`book.ts`),
  the versioned reading position and per-chapter progress
  (`position.ts`), and page-record building from container listings /
  extraction manifests (`records.ts`).
- `src/main.ts` — thin server hooks over the logic: `detect`, `sourceMeta`,
  `searchMeta`, `coverLocal`, `listFiles`, `imageHashes`. Archive pages
  are addressed as virtual paths (`book.cbz!第1话/001.png`) for
  probing/hashing/covers; full materialization happens only in
  `listFiles`, i.e. on first preview (with the host's per-entry progress
  surfaced by the reader).
- `src/render/` — thin React adapters: the book hook (`useMangaBook`),
  chapter+page position (`useMangaReaderState`), first-materialization
  progress (`useExtractProgress`), the chapter directory drawer
  (`ChapterList`), and the scroll/paged views.

## SDK packages

`@hoardodile/*` dependencies resolve from the npm registry (`^0.1.1`):
`pnpm install` pulls the published SDK directly — no tarballs, no
`pnpm-workspace.yaml` overrides.
